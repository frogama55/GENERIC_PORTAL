# プライバシー設計メモ（外部送信しないことの担保・開発者向け）

> **【スマホ版（NexPortal Mobile）での読み替え】**
> このメモは Chrome 拡張版をもとに書かれています．スマホ版はユーザースクリプトなので，
> `manifest.json` による権限の仕組みがありません．同じ方針を次の形で担保します．
>
> - **動作範囲**：ヘッダの `@match` を対象ポータル（`https://portal.chibatech.ac.jp/uprx/*`）だけに
>   限定する（`build.mjs` 内）．SSO ドメインは対象に含めない．
> - **通信**：`@grant` は `GM.getValue` / `GM.setValue`（設定の保存）だけ．オリジンをまたいで通信できる
>   `GM.xmlHttpRequest` は**要求しない**．そのためスクリプトが使えるのは通常の `fetch` だけで，
>   ブラウザの同一オリジン制約がそのまま掛かる．コード上の通信は添付取得（ポータル自身への
>   same-origin `fetch`）の1か所のみ．
> - **拡張版より弱い点**：拡張版は「権限が無いので他ドメインへ送れない」とブラウザが保証していたが，
>   スマホ版にはその保証が無い．`@grant` を増やさない・外部URLを書かない，というコード上の規律と
>   レビュー（下のチェックリスト）で守る．
> - **ページ側スクリプト**：`"world": "MAIN"` の代わりに，`inject.js` が `page-bridge.js` を
>   `<script>` 要素として差し込む．中身は拡張版の `loading-bridge.js` と同じ（イベントの変換だけ）．
> - **ビルド**：1ファイルにまとめるため `build.mjs` を使うが，外部ライブラリは使わず，ファイルを
>   順に連結するだけ．`dist/` の生成物もリポジトリで公開しており，全部読める．
> - **更新**：利用者のアプリが GitHub の公開リポジトリから新しい版を取得する（適用は利用者の操作）．
>   リポジトリへの push 権限がそのまま配布の権限になるので，アカウントの保護（2要素認証）が前提．
> - **設定の保存先**：`GM.setValue`（アプリの保存領域）．使えない環境では localStorage．どちらも端末内．

> このファイルは開発者向けの技術メモです．利用者向けの正式なプライバシーポリシーは
> [PRIVACY_POLICY.md](../PRIVACY_POLICY.md)（リポジトリ直下）を参照してください．

この拡張はいかなるデータも拡張の外へ送信しない．

## 送信しないことの根拠（コードレベル）

- **ネットワーク権限を持たない（ポータル以外へは送れない）**
  `manifest.json` の `permissions` は `storage` のみ．`host_permissions` は
  `https://portal.chibatech.ac.jp/uprx/*` のみ．外部ドメインへの権限は一切ないため，
  たとえバグがあってもポータル以外へは通信できない（構造で担保）．
- **通信はポータルへの same-origin のみ**
  添付プレビュー機能(attachment.js)だけは `fetch` を使うが，送信先は **ポータル自身**
  （`form.action` = 同一オリジンの Bsd00701.xhtml）に限定．第三者へは一切送らない．
  クッキーはブラウザが自動付与するだけで，拡張はその値を読まない（セッションは HttpOnly）．
  取得したPDFは表示のための一時 blob で，保存も外部送信もしない．詳細は docs/security.md．
- **background (service worker) を持たない**
  定期処理・自動ポーリングの類は実装していない．
- **保存先はローカルのみ**
  設定（enabled / largeText）は `chrome.storage.local` にのみ保存する．
  `chrome.storage.sync`（Googleアカウント同期）も使っていない．
- **認証情報を扱わない**
  ID・パスワード・トークンの読み取り／保存／自動入力は行わない．
  SSOドメイン（`sso.chibatech.ac.jp`）には content script を注入しない．

## やらないこと（ハードルール）

- 外部サーバー・APIへのデータ送信（テレメトリ・分析含む）
- 認証情報の保存・自動入力・自動再ログイン
- ポータルへのPOST等の書き込み・データ変更（読み取り専用に徹する）
- 短間隔ポーリング・ループでの連続アクセス
